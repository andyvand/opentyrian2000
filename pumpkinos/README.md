# OpenTyrian 2000 PumpkinOS port

A native [PumpkinOS](https://github.com/migueletto/PumpkinOS) (PalmOS
re-implementation) port of OpenTyrian 2000. The game code is the normal
OpenTyrian code; this directory provides a small SDL2 compatibility layer on
top of the PalmOS API, the PalmOS application entry point and form, and
bundles the Tyrian 2000 data files into the PRC as resources, so the
application is self-contained.

## Building

```sh
make -f Makefile.pumpkinos PUMPKIN=/path/to/PumpkinOS
```

`PUMPKIN` (default `~/Downloads/PumpkinOS`) must point at a PumpkinOS
checkout that has already been built (`bin/libpumpkin`, `bin/libpit`,
`tools/pilrc` and `tools/prcbuild` must exist). The build produces
`OpenTyrian.prc` (about 8.7 MB, most of it game data) and installs it into
`$(PUMPKIN)/vfs/app_install/`; PumpkinOS deploys it on next boot and it shows
up in the Launcher as "OpenTyrian 2000".

`DATA_DIR` (default `data`) selects the data set that gets bundled. The
build products land in `obj_pumpkinos/<OSNAME>-<MACHINE>/`, so builds for
several targets can coexist.

The `dlib` resource id inside the PRC encodes the host OS/CPU/word-size
triple and must match the values baked into `libpumpkin` when it was built
(`dlib` id = `SYS_OS*64 + SYS_CPU*8 + SYS_SIZE`). Override `SYS_CPU` /
`SYS_SIZE` on the make command line if the detected values do not match
your PumpkinOS build.

On macOS the dlib's reference to libpumpkin is rewritten to
`@rpath/libpumpkin.dylib` and the library is code signed, like the other
PumpkinOS applications.

### Running it directly (macOS)

PumpkinOS can start the game instead of the Launcher ("single application"
mode): copy `script/pumpkin.lua`, add `app = "OpenTyrian 2000"` and
`mode = 1` to the `pumpkin.start { ... }` table and run from the PumpkinOS
directory

```sh
DYLD_LIBRARY_PATH=./bin:/usr/local/lib PATH=./bin:$PATH \
  ./pumpkin -d 1 -f pumpkin.log -s libscriptlua my.lua
```

(`/usr/local/lib` is where SDL3, used by the PumpkinOS display backend,
lives). A PRC waiting in `vfs/app_install` is deployed on that boot and the
game is started on the following one.

### MS-DOS (DJGPP)

```sh
make -f Makefile.pumpkinos OSNAME=msdosdjgpp MACHINE=i686 PUMPKIN=/path/to/PumpkinOS
```

The DOS build of PumpkinOS is one static `pumpkin.exe`; the game is a DXE3
module (`dxe3gen`) carried in the PRC's `dlib` resource and loaded with
`dlopen`, like the CrispyDoom games. The build installs `OpenTyri.prc` (an
8.3 name) into `$(PUMPKIN)/vfs/app_inst/` and writes
`$(PUMPKIN)/src/msdos/dxesyms_tyrian.c`, the table of every symbol the module
imports (generated by `dxe3res.py` from the module); `pumpkin.exe` exports the
listed symbols to the module, so relink it after the table changes:

```sh
make -C /path/to/PumpkinOS/src/msdos -f GNUMakefile OSNAME=msdosdjgpp MACHINE=i686
```

A DXE3 module can only import what the host exports, so the C library
functions the game needs that `pumpkin.exe` does not export are part of the
module: `pumpkinos/dos_libc.c` (`sinf`, `cosf`, `sin`, `atanf`, `sqrtf` on the
x87 FPU, `roundf`, `snprintf` over the host's `vsnprintf`, `strlcpy`,
`strlcat`, `strncat`) and a self-contained `powf()` in `src/loudness.c`
(`PUMPKINOS && DOS`). The exit unwinding uses the compiler's built-in
setjmp/longjmp on DOS for the same reason. To check a new module, list its
imports with `python3 -I $(PUMPKIN)/src/dxe3res.py obj_pumpkinos/msdosdjgpp-i686/OpenTyrian.dlib`.

To run it in DOSBox-X from a DOS runtime directory holding `bin/pumpkin.exe`
and `vfs/`:

```sh
dosbox-x -conf dosbox-x.conf -c "mount c /path/to/dosdir" -c "c:" -c "cd bin" \
  -c "pumpkin.exe -d 1 -app \"OpenTyrian 2000\""
```

## Usage

- Launch "OpenTyrian 2000" from the Launcher. The window requests 640x430
  pixels (title bar plus the 320x200 game screen pixel-doubled). PumpkinOS
  clamps that to its display and takes its window border off, so the game
  is scaled to fill the window ("Fit 8:5" in the setup menu, the default);
  "Integer" uses the largest whole multiple that fits and "Center" shows it
  unscaled.
- Configuration (`opentyrian.cfg`), the Tyrian save file (`tyrian.sav`,
  `tyrian.cfg`) and recorded demos are stored in the PalmOS VFS at
  `/PALM/Programs/OpenTyrian/` (host path:
  `<PumpkinOS>/vfs/app_card/PALM/Programs/OpenTyrian/`).
- The **Game** menu has About and Quit. Closing the application from the
  PumpkinOS window manager also quits the game.

### Controls

The keyboard works as in the other OpenTyrian builds (arrow keys move,
Space fires, Enter changes the fire mode, Ctrl/Alt fire the sidekicks,
Escape opens the in-game menu, P pauses; all of this can be changed in the
game's setup menu). Key names in the configuration file use the SDL2
names, so an `opentyrian.cfg` from another build can be reused.

The mouse works in the menus and for the mouse control mode. The PumpkinOS
window manager reserves the right mouse button for window management, so
only the left button reaches the game.

Not available on PumpkinOS: joysticks, network play, MIDI music
(the OPL music is used) and fullscreen mode.

## Implementation notes

- **SDL2 layer** (`SDL2/SDL.h`, `sdl_shim.c`): the game sources are
  compiled unchanged against a small re-implementation of the SDL2 API they
  use: 8 bpp software surfaces, the event queue, timing, the audio device,
  the S8 to S16 sample conversion and the scancode name table. Scancode
  values, modifier bits and event numbers are the real SDL2 values.
- **Video** (`tyr_video.c`, `pumpkin_app.c`): replaces `video.c` and the
  software scalers. `JE_showVGA()` converts the 320x200 8 bpp frame to
  RGB565 through the palette and the PalmOS side scales it by an integer
  factor into `BmpGetBits(WinGetBitmap(WinGetDisplayWindow()))`, then calls
  `pumpkin_screen_dirty()`, like the Doom and GNUBoy ports. The byte order
  of the window bitmap is detected at the first frame by painting one pixel
  through the Window manager and reading it back, so 16 and 32 bpp windows
  of either byte order work. Scaling is nearest neighbour through
  precomputed lookup tables; the four scaling modes of the setup menu
  (Center, Integer, Fit 8:5, Fit 4:3) are honoured.
- **Input**: the keyboard and the pointer are polled with
  `pumpkin_status()` whenever the game polls for events (hardware key bits
  for the arrows and F1-F4, modifier bits for Shift/Ctrl/Alt, the 128-bit
  ASCII bitmap for the rest, pointer position and buttons); changes are
  turned into SDL key, text input and mouse events. PalmOS key events carry
  no key-up edges, which is why polling is used.
- **Audio**: `SDL_OpenAudioDevice()` is implemented on `SndStreamCreate`
  (16-bit stereo at the game's 44100 Hz; the game's mono mix is
  duplicated). The game's pull callback (OPL music plus sound effects) runs
  from the stream callback under a mutex that also backs
  `SDL_LockAudioDevice()`. Following the PumpkinOS stream contract, the
  callback always returns a full buffer (silence while paused) and paces
  itself to real time.
- **Timing and events**: `SDL_Delay()` and `SDL_PollEvent()` pump the
  PalmOS event loop, so the form, its menu and the window manager stay
  responsive while the game runs its own main loop inside `PilotMain`.
- **Files** (`pumpkin_compat.h`, `pumpkin_stdio.h`, `tyr_file.c`,
  `pumpkin_app.c`): the stdio calls in the game are redirected (through a
  force-included header) to a small file layer. `data_dir()` returns the
  pseudo directory `res:`, under which every Tyrian data file is a `tdat`
  resource of the PRC (`gen_data.sh` generates the pilrc statements and the
  name-to-id table from the `data/` directory at build time). All other
  paths are PalmOS VFS files.
- **exit()**: a PumpkinOS application is a shared library inside the
  PumpkinOS process, so `exit()` must never be called. It is redirected to
  `tyr_exit()`, which unwinds to `PilotMain` with `longjmp`; the audio
  stream is closed there.
- **Source changes**: `src/opentyr.c` names its entry point `tyrian_main`
  and skips the macOS bundle queries when `PUMPKINOS` is defined;
  `src/config.c` takes the user directory from the PalmOS side.
  Everything else is untouched.
- **Icon**: `opentyrian.bmp` is generated from
  `opentyrian2000.iconset/icon_32x32.png` by `png2bmp.py` (green is the
  transparent colour declared in `resource.rcp`).
- Log lines are written to the PumpkinOS log with the tag `TYRIAN`.
